# 架构与数据流

## 分层

| 层 | 组件 | 主要职责 |
| --- | --- | --- |
| 端侧 | `vino_iPhone` | 相机采集、CoreML 推理、模型安装、租约校验、数据上传 |
| 现场侧 | `vino_Desktop` / 本地 Web 节点 | 局域网控制、批量控制、模型分发、现场缓存和转发 |
| 云侧 MVP | `vino_cloud` | 账号、授权、模型票据、加密包、离线租约、ingest |
| 云侧正式平台 | `vino_platform` | 商城、订单、开发者、审核、SKU、授权、财务、审计 |

## 控制链路

1. iPhone 通过 Bonjour 广播 `_vino-control._tcp`。
2. Desktop 或本地节点用 TCP 连接默认端口 `48920`。
3. 双方用 JSON Lines 发送 `vino.control/1` 信封。
4. 远程命令使用 `productUUID`、`pointIndex`、`jobId` 作为追踪上下文。
5. iPhone 推送状态、心跳、能力、推理结果和低频预览帧。

## 模型授权下载链路

1. iPhone 调用 `POST /api/cloud/v1/auth/login` 登录。
2. iPhone 调用 `GET /api/cloud/v1/models` 获取当前账号可用模型。
3. iPhone 调用 `POST /api/cloud/v1/models/:id/download-ticket` 获取短时下载票据。
4. Cloud 校验 Entitlement、设备绑定和租约策略。
5. iPhone 调用 `GET /api/cloud/v1/download/:ticketId` 下载 `vino-aesgcm-v1` 加密包。
6. iPhone 使用 `ticketSecret:modelId:deviceId:modelBuildId` 派生密钥解密。
7. iPhone 校验明文 `sha256`，安装为 CoreML 运行时模型。
8. iPhone 调用 `POST /api/cloud/v1/licenses/lease/renew` 续租。

## ingest 链路

1. iPhone 拍照、录像或生成推理结果。
2. `AssetUploadService` 先写入本地缓冲。
3. 如果 `localNodeBaseURL` 可用，上传到 `/api/local/v1/ingest/*`。
4. 如果 Cloud 登录会话可用，上传到 `/api/cloud/v1/ingest/*`。
5. 成功后移除本地缓冲任务。

## 正式平台目标

`vino_platform` 应把当前文件态 MVP 拆成生产组件：

- PostgreSQL：账号、组织、订单、授权、设备、审计。
- Object Storage：模型文件、加密产物、图片、视频、附件。
- Redis：会话、下载票据、限流、短锁。
- Queue：模型扫描、格式检查、通知、结算、转码。
- API/BFF：Web 平台 API 和 iPhone 兼容 API。
