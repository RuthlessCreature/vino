# 项目总览

## 定位

`vino` 面向工业检测现场，把 iPhone 采集、边缘 CoreML 推理、模型授权下载、离线租约和图片/结果回传组织成一套端云协同系统。

商业叙事应保持 B2B 企业服务：Web 侧做购买、授权、审核、结算和运营；iPhone 侧只做现场执行，不做 App 内商城和支付。

## 目录职责

| 目录 | 职责 | 当前状态 |
| --- | --- | --- |
| `vino_iPhone` | iPhone 原生 App，相机预览、控制 Overlay、模型管理、云登录、下载、租约、上传 | 可编译工程，主链路已落地 |
| `vino_cloud` | 零依赖 Node.js 云端 MVP，账号、模型授权、下载票据、AES-GCM、ingest | 演示可用，不是生产架构 |
| `vino_platform` | 模型交易、授权、审核、结算、运营后台 | 文件态 MVP + 规划文档 |
| `vino_Desktop` | 上位机设备发现、批控、模型分发、本地节点能力 | 调试和现场运维工具 |
| `docs` | 根项目架构、协议、功能清单、商业策略 | 已有主设计材料 |
| `shared` | 协议 schema 和 JSON 示例 | 用于端侧对齐 |
| `models` | CoreML 演示模型和测试模型 | 云端可自动发现 |

## 本地启动

```sh
cd vino_cloud
npm start
```

默认端口：`8787`

```sh
cd vino_platform
npm start
```

默认端口：`8797`

```sh
cd vino_iPhone
xcodebuild -project vino_iPhone.xcodeproj -scheme vino_iPhone -sdk iphonesimulator -configuration Debug build CODE_SIGNING_ALLOWED=NO
```

## 当前关键结论

- 控制面是 `Bonjour + TCP JSONL`，协议固定为 `vino.control/1`。
- 模型下载和续租接口保持 `/api/cloud/v1/*`，方便 iPhone 兼容。
- `vino_cloud` 是 MVP 参考，不建议直接扩成生产交易平台。
- 正式 Cloud 端应从 `vino_platform` 方向生产化：数据库、对象存储、队列、RBAC、审计、支付和部署。
- iPhone 端已经跑通云登录、模型列表、下载票据、加密下载、安装、租约续期和上传缓冲，但还要补生产级体验和可靠性。
