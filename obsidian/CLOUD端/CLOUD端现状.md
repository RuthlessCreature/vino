# CLOUD 端现状

## 两套 Cloud 代码的定位

| 目录 | 定位 | 端口 | 说明 |
| --- | --- | --- | --- |
| `vino_cloud` | 云端授权和模型分发 MVP | `8787` | 零依赖 Node.js，适合演示和 iPhone 联调 |
| `vino_platform` | 正式交易平台方向和文件态 MVP | `8797` | 覆盖商城、订单、开发者、审核、授权、财务、审计 |

## `vino_cloud` 已有能力

- Web 控制台。
- 用户管理和演示账号。
- 模型自动发现：扫描仓库根目录 `models/` 下的 CoreML 文件。
- 模型授权分配：模型必须分配给用户后 iPhone 才可见。
- 下载票据：`POST /api/cloud/v1/models/:id/download-ticket`。
- 加密下载：`vino-aesgcm-v1`，算法为 `AES-256-GCM`。
- 离线租约：永久和固定截止时间两种续租模式。
- ingest：图片、推理结果、日志、统计。
- 兼容入口：`/uploadLog`、`/uploadStat`、`/uploadData`。

## `vino_platform` 已有能力

- 多角色账号：超管、运营、审核员、财务、采购管理员、现场操作员、开发者。
- Web 后台：总览、商城、开发者、交易授权、模型商品、终端数据、服务定制、财务发票、运营系统。
- 模型商城：搜索、分类、试用、收藏、评价。
- 开发者中心：入驻、模型草稿、提交审核、平台审核。
- 交易闭环：订单、优惠券、人工确认收款、生成 Entitlement。
- 授权闭环：手动授权、组织/用户分配、撤销、离线租约。
- iPhone 兼容 API：登录、模型列表、下载票据、下载模型、续租、ingest。
- 审计日志：关键动作写入审计。

## 当前边界

- 两套 Cloud 都是文件态状态存储，不是生产数据库。
- 模型和图片资产仍主要走本地磁盘，不是对象存储。
- 密码、token、票据和下载安全是 MVP 强度，生产必须升级。
- 大文件上传/下载缺少生产级流式处理、限流、断点和监控。
- `vino_cloud` 适合保留为演示环境，正式平台应沿 `vino_platform` 生产化。
